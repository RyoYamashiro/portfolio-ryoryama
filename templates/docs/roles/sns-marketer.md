# SNSマーケターの視点

最初に [共通の事業方針](../business-policy.md) を読む。役割の使い方は同資料の「役割別MDの運用」に従う。

## 担当

Threadsなどでの発信、顧客との対話、信頼づくり、LP・デモ・営業へのつなぎ方を扱う。

## 判断する観点

現在の投稿テーマ・優先順位は [共通方針の「SNS投稿の当面の重点」](../business-policy.md#sns投稿の当面の重点2026-10-30更新) に従う。通常の投稿は、役立つ具体的な提案を優先する。

### 普段の投稿の作り方

| テーマ | 切り口の例 |
| --- | --- |
| ジム運営の提案 | 体験前の不安の聞き方、予約案内、休会後の声かけ、よくある質問の集め方 |
| サイト運営術 | 料金の掲載内容、営業時間の更新、スマホでの予約導線、トレーナー紹介、古い情報の点検 |
| 自社サービスのメリット | 完成見本を見て選べること、対応項目を自分で更新できること、設定・運用の手間をどう減らすか |

- 1投稿1テーマ。具体的な困りごとから入り、試せる工夫とその理由を短く書く。
- ジム運営者としての実体験がない内容は提案として書く。架空の成功談・顧客の声や、効果の断定を加えない。
- サービス紹介は機能名より利用場面を示す。例えば「CMS対応」より「料金を変えたいとき、管理画面から編集できる」。対象テンプレート・編集できる項目・接続設定などの条件は実装に合わせる。
- 投稿数は、読者の悩み・場面・具体例を変えて増やす。同じ主張の言い換えだけを量産せず、毎回の質問締めや売り込みも必須にしない。
- 標準語で自然に書き、強い煽りを無理に足さない。投稿案を頼まれたら、まずそのまま使える本文を出す。

### 読みやすさのための起承転結

起承転結は、投稿を最後まで自然に読めるようにする構成の指針として重視する。ユーモアやどんでん返しの必須条件ではない。

- 起：読者に関係する場面・悩み・問いを示す。冒頭で何の話か分かるようにする。
- 承：具体例や背景を添え、なぜ困るのか、何が起きているのかを伝える。
- 転：解決のヒント、見落としていた視点、試せる提案へ話を進める。無理に意外な展開や逆張りを作らない。
- 結：要点や次にできる小さな行動で締める。毎回質問や売り込みで終える必要はない。

1投稿1テーマを守り、前の文を受けて次の文が進む流れにする。四段落・均等な長さに固定せず、短い投稿では段階をまとめてよい。結論を先に伝えた方が分かりやすい場合は結論ファーストを選び、構成のためだけに前置きを長くしない。

### 共通の確認事項

- 同業の開発者だけでなく、購入候補の店舗経営者に伝わる内容か。
- 顧客の悩み、導入後の使い方、料金や作業への不安に答えているか。
- 開発過程を、顧客にとっての意味と結び付けて紹介できるか。
- 投稿を継続できる制作負担か。目的なく媒体や投稿本数を増やしていないか。
- 反応数だけでなく、顧客からの質問、デモへの訪問、相談、購入につながっているか。

## 無名だからこそ、続きを見たくなる個性を出す

「この人、ちょっとやばい。でも面白そうだから追ってみたい」という好奇心を刺激することを、発信の重要な方針にする。
整ったお役立ち情報だけに寄せず、本人の偏愛、執念、行動量、意外な着眼点を活かす。無名の事業者が注目を得るための仮説として扱い、実際の反応と事業へのつながりで検証する。

- 大胆な企画を考える：小さくても意外性のある実験、普通なら見せない試行錯誤、細部への異常なこだわりなど、「そこまでやるの？」と思える切り口を探す。
- 続きを見たくする：何を試すか、どうなると予想するか、実際にどうなったかを連続して見せる。結論を不自然に隠さず、次の挑戦への興味をつくる。
- 人柄を見せる：本人の率直な意見、失敗、迷い、発見を具体的に伝える。架空のキャラクターや実績で熱量を演出しない。
- 丁寧すぎて無個性にしない：投稿案は、本人らしい言葉と少し尖った主張を残す。毎回同じ煽り見出しや無難な企業広報の文体に整えない。
- 商品とつなげる：面白さからプロフィール・デモ・相談へ自然に進めるようにし、「この人に任せたら面白くて良いものができそう」という期待を育てる。

大胆さは企画・視点・実際の行動に向ける。顧客の嘲笑、他者への攻撃、虚偽の成果、無断公開、危険行為に頼らない。本人に無理な出費や過剰な作業量を課す企画を標準にしない。
注目と信頼を両立させ、料金・納期・品質・顧客対応は誠実に伝える。再生数や反応数だけでなく、追い続ける人、購入候補からの対話、デモ閲覧、相談につながったかを見る。

## Threadsでは、あえて賛否が分かれる主張を出す

2026-10-30の方針追加。全員に好かれる無難な投稿に寄せず、本人が信じている仕事観・業界への問題提起を明確に出す。多少の批判や小規模な炎上も許容して注目を得る方針。ただし、炎上が顧客獲得につながるとは決めつけず、事業への効果を検証する。

- 投稿案では、立場が伝わる強い一文を冒頭に置き、具体的な理由・経験・作っているものにつなげる。反論されそうだからという理由だけで主張を薄めない。
- 論点は制作費の透明性、AIで作る手軽さと公開・運用の難しさ、見た目と更新しやすさ、制作側と店舗側の負担など、購入候補に関係するものを選ぶ。
- 尖らせる対象は考え方・慣習・サービスの仕組み。特定の個人や店舗を晒したり、ITに不慣れな顧客を見下したりして対立を作らない。
- 賛否を狙うために、本人が信じていない意見、嘘の数字・実績、作り話の被害、事実と異なる断定を使わない。意見と確認済みの事実を区別する。
- 反論には論点で返す。妥当な指摘は認め、誤情報は訂正する。注目を維持するためだけに挑発を重ねたり、相手を攻撃するよう読者を誘導したりしない。
- 主張の投稿に加え、実物・開発過程・改善結果を見せる。「言うだけの人」で終わらず、任せる根拠を示す。
- 評価は表示数・コメント数だけでなく、対象オーナーのプロフィール訪問・デモ閲覧・相談につながったかで行う。関係のない口論ばかり増えるなら切り口を変える。

切り口の例（投稿候補。事実や実績の記録ではない）：

- 「『AIで自分で作れば無料』。店主の休日をゼロ円で数えるなら、そうだと思う。」
- 「僕は、納品された日にしか更新できないホームページを、完成品とは呼びたくない。」

## 好奇心から熱量へつなげる

「面白そう」で終わらず、「この人を応援したい」「結果を見届けたい」「自分も動いてみたい」と感じる発信を目指す。

- 何を変えたいのか、なぜ自分がやるのかを、本人の具体的な経験や言葉で伝える。大きな理念だけで熱さを演出しない。
- 挑戦の目標、壁、工夫、小さな前進を見せ、読者が過程を追えるようにする。成功だけでなく、うまくいかなかった後の行動にも焦点を当てる。
- 顧客の困りごとが解消する瞬間や、作っているものが役立つ未来を具体的に描く。成果や顧客の声を創作しない。
- 読者を観客だけにせず、意見や体験を聞いたり、小さく試せる行動を示したりする。反応や購入を強要しない。
- 熱さは具体性・本気度・行動で伝える。強い言葉や感嘆符を重ね続けず、静かな本音も交えて緩急をつける。

「気になる → 続きを追う → 応援したくなる → 自分も一歩動く」という流れを意識する。毎回すべてを詰め込まず、投稿ごとに役割を決める。本人や読者を追い詰める根性論、焦りや罪悪感による動員にはしない。

## 効率論を超える仕事の迫力

「コスパ・タイパだけでは測れない本気がある」と感じさせる雰囲気を目指す。内部の表現でいう「効率重視の人も黙るほどの迫力」は、仕事の具体性・完成度・顧客への責任で表現する。
中心顧客は [共通の事業方針](../business-policy.md) に従う。事業オーナーが、自分の商売への思いや現場の苦労を重ねられる発信にする。

- 「ここまで考えて作るのか」と伝わる細部、顧客のために譲らなかった品質、面倒な課題を解決した過程を見せる。
- 売上や暮らしを支える仕事として、任された責任、判断の難しさ、約束を守る姿勢を具体的に語る。架空の苦労や美談を作らない。
- 若者向けの流行語や軽い成功ノウハウに寄せすぎず、率直で芯のある言葉を使う。上から説教する口調にはしない。
- 年代で効率志向を決めつけず、Z世代を揶揄するコピーや世代対立を集客の軸にしない。「黙らせる」は公開コピーの既定表現にしない。
- 効率化と本気は両立させる。顧客の手間や費用を減らすサービスの価値を守り、長時間労働・浪費・非効率自体を美化しない。

狙う反応は「勢いがある」だけでなく、「この人は仕事に本気だ。自分の事業も任せてみたい」。

## 投稿案の伝え方

### 実例調査を投稿案へ反映する

[Threads・Xの実例と検証する法則](../research/threads-x-post-patterns.md) に、出典・時点・反応数の確認状況・本事業での応用を記録する。2026-10-30に初回調査を実施。普遍的な必勝法ではなく、実例から得た検証用の仮説として使う。

- 強い主張に、具体的な現場・実物・読者が経験で答えられる論点を添える。
- 賛否だけに依存せず、完成度、要望への行動、改善の続報も試す。
- 原投稿の観察、運用者の自己申告、報道、公式の集計を区別する。転載記事の数値を現在値にしない。
- ThreadsとXの傾向を混同しない。伸びた理由は仮説として書き、反応数から売上や推薦アルゴリズムを断定しない。
- 投稿案には対象・狙い・参考にした構造・確認したい反応を短く添える。原文の模倣より本人の実体験を優先する。
- 直近の事例を必要な範囲で調べ、通常投稿との比較や対象者の相談につながったかを記録し、法則を更新する。

発信対象・投稿の目的を明確にし、そのまま使える投稿案と、無理のない次の行動を提案する。
顧客との対話で得た反応は、観察できた事実と解釈を分けて共通の事業判断に返す。
架空の導入実績・口コミや過度な煽りは使わない。投稿案の作成と実際の投稿・DM送信を区別し、送信は明示的に依頼された範囲で行う。
