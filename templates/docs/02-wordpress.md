# WordPressと比べるとどうなの？💅

最初に大事なこと！ **WordPressもヘッドレスCMSとして使える**よ。
「WordPressかヘッドレスか」は完全な二択じゃないの。WordPressのREST APIは、コンテンツをJSONで別アプリへ渡せる仕組みを提供してるよ。
出典：[WordPress REST API Handbook](https://developer.wordpress.org/rest-api/)

ここでは「WordPressのテーマで表示する一般的な構成」と「CMS＋別の表示アプリ」を比べるね。

## 得意・不得意を知って選ぼ！

| 観点 | 通常のWordPress構成 | ヘッドレス構成 |
| --- | --- | --- |
| 最初の完成まで | テーマと管理画面を一緒に使える | 表示側とAPI連携を用意する必要がある |
| 表示の自由度 | テーマの仕組みに沿って作る | 表示側の技術や構成を選びやすい |
| 複数媒体への配信 | APIを使う追加設計も可能 | Web・アプリなどで同じデータを使う設計に向く |
| 編集とプレビュー | テーマと一体で確認しやすい | 下書き表示の認可やプレビュー連携を設計する |
| プラグイン | テーマ向け機能を利用しやすい | 表示側へそのまま反映されない機能もある |
| SEO | テーマやプラグインを活用できる | メタ情報・HTML生成・サイトマップ等を表示側で整える |
| 保守 | WordPress・テーマ・プラグインを管理 | CMSと表示アプリ、両方の保守が必要 |
| 費用 | ホスティングや有料機能に左右される | CMS料金・API利用量・表示側のホスティング等に左右される |

これは構成から考えられる一般的な比較だよ。実際の難易度や費用は、選ぶサービスと要件で変わるの。
ヘッドレスにしただけで速くなる・SEOが強くなる・安全になる、とは言えないよ〜。
たとえば今回のNext.jsアプリは、Reactのコンポーネントがブラウザで記事を取得する方式。Next.jsへの移行だけで記事本文のHTML生成まで変わるわけではないよ。検索やSNS共有を意識した販売版なら、記事入りHTMLを先に作る方式も学びたいね！

## 現状はどう？

2026年10月26日に確認した公式資料では、WordPressはREST APIを提供し、microCMSはコンテンツの取得・登録などに使うAPIを提供しているよ。
つまり「記事をAPIで受け取る」は既存サービスで取り組める方法だよ。
ただし、この確認だけで市場シェアや販売需要、日本で一番売れる技術までは判断できないの。
出典：[WordPress公式](https://developer.wordpress.org/rest-api/)、[microCMS コンテンツAPI](https://document.microcms.io/content-api/introduction)

microCMSにはAPIキーによる権限設定があるよ。つなぐときは「公開記事を読む権限」と「下書き・書き込みの権限」を分けて考えよ。
出典：[microCMS APIキーと権限管理](https://document.microcms.io/content-api/x-microcms-api-key)

## 将来性は？ ここからは見通しだよ！

Web以外にも同じ記事を届けたい、表示技術を変えたい、という用途には、データと表示を分ける設計が役立つと考えられるよ。
一方、更新が少ない小規模サイトなら、一体型CMSの方が導入も運用もラクな場合があるの。
ヘッドレスが全部を置き換える未来や、テンプレ販売での成功を保証する話ではないよ。

長く使える力は、特定サービスの設定を暗記するだけじゃなくて、**記事の項目を決める・APIを理解する・エラーを扱う・買った人が更新できるようにする**こと。
このサンプルも、その土台を先に練習できる形にしたよ！

## 販売で磨くならここじゃん！

「ブログ用」「店舗のお知らせ用」など、最初は1用途に絞ろう。
見た目に加えて、記事モデル・見本データ・接続手順・更新手順までそろっていると、購入者が完成まで進みやすいよ。
どの用途に需要があるかは、実際の利用者への聞き取りや小さな販売で確かめようね。

料金・利用上限・ライセンス・再配布条件は変更されることがあるから、販売時に採用サービスの最新条件を確認しよ！
今は比較表を全部暗記しなくてOK。「どちらにも合う仕事がある」ってわかれば十分だよ〜。
