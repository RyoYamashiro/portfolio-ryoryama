# NAGIのCMS設定・動作確認

## 今回できること

microCMSの標準管理画面から、`/gym-premium` のジム名・トップの見出し・各セクションの文章・5か所の写真・料金プラン・FAQ・住所・営業時間・予約URL・SEOタイトル／説明を更新できます。
編集・ログイン・下書き保存・公開はmicroCMS側が担当し、Next.jsは公開データを取得して表示します。独自の管理画面や書き込みAPIは今回作りません。
STELLA `/gym` の接続は別APIです。[STELLA設定ガイド](stella-microcms-setup.md) を参照してください。ブログ、簡単モード、テーマ色の保存は接続対象外です。

## 最初の設定（制作担当者向け）

### 1. microCMSでサービスとAPIを作る

1. [microCMS](https://microcms.io/) にログインし、サービスを作成します。利用プランと上限は契約時に確認してください。
2. APIを作成し、表示名を「ジムサイト」、エンドポイントを `gym-premium` にします。
3. **オブジェクト形式**を選びます（リスト形式ではありません）。
4. スキーマ設定の「ファイルインポート」から、このリポジトリの [gym-premium-schema.json](microcms/gym-premium-schema.json) を選びます。
5. 項目を確認します。基本情報 → 各画面の文章 → 写真 → 料金 → FAQの順です。コード用のIDは制作担当者が設定し、店舗オーナーは日本語の表示名で編集します。

独自に生成したスキーマのため、実アカウントでのインポートはまだ未検証です。公式仕様を基に作成しています。インポートできない場合は、JSONの `fieldId`・`name`・`kind` を参照して同じ項目を手動作成してください。フィールドIDは変更しないでください。

### 2. 最初の内容を入力して「公開」する

文章にはNAGIの初期値を用意しています。必須は「ジム名」「検索・共有用タイトル」「検索・共有用の説明」「トップの見出し」「料金プラン」です。

最初のテストは料金プランを1件だけ作ると簡単です。

| 項目 | 入力例 |
| --- | --- |
| ジム名 | 動作確認ジム |
| トップの見出し | 今日から、自分のペースで。 |
| 料金プラン → プラン名 | 月4回プラン |
| 月額（税込・円） | `33000`（カンマ・円記号は付けない） |
| 内容 | 個別指導、カウンセリングなどを1行に1項目 |
| おすすめ表示 | 必要な場合だけON |
| FAQ | 「初心者でも大丈夫？」などを1件追加 |

料金は1〜3件、0〜10,000,000円の整数です。内容は1〜10行、FAQは最大30件。すべて平文で入力し、HTMLやリッチエディタは使いません。
写真は任意です。未設定なら既存画像を使います。microCMSの画像フィールドへJPEG・PNG・WebP等をアップロードし、画像の説明も入力してください。

全項目の入力例は [gym-premium-content-example.json](microcms/gym-premium-content-example.json) にあります。これは**内容の見本**で、スキーマとしてインポートするファイルではありません。

### 3. 読み取り専用APIキーを設定する

microCMSのAPIキー設定で、このAPIへの **GETのみ**を許可するキーを使います。書き込み・マネジメントAPIの権限は不要です。ログインはmicroCMSのアカウントで行い、可能なら2要素認証を設定してください。

プロジェクトルートに `.env.local` を作り、次を記入します。既存ファイルがあれば他の設定を残して追記してください。

```dotenv
MICROCMS_SERVICE_DOMAIN=あなたのサービスID
MICROCMS_API_KEY=あなたの読み取り専用キー
MICROCMS_GYM_ENDPOINT=gym-premium
```

サービスIDは `https://サービスID.microcms.io` のサービスID部分だけです。`https://` や管理画面のURL全体を入れません。
APIキーをチャット、画面共有、公開リポジトリへ貼らないでください。`NEXT_PUBLIC_` を付けません。`.env.local` はGit対象外、空欄の見本は [.env.example](../.env.example) です。

### 4. 接続を確認する

```sh
npm run cms:check
npm run dev -- --port 3010
```

既に開発サーバーが動いている場合は、環境変数・Next.js設定を反映するため一度停止して同じポートで再起動します。別のサーバーを重複起動しないでください。
`cms:check` が「接続OK」になったら <http://127.0.0.1:3010/gym-premium> を開きます。
管理画面はmicroCMSの「ジムサイト」です。ローカルの `/admin` は別の旧教材で、このページの編集には使いません。

## 日々の操作（店舗オーナー向け）

1. microCMSの「ジムサイト」を開く。
2. 変えたい場所の名前を探す。「トップの見出し」「料金プラン」「よくある質問」などです。
3. 入力内容を変更する。料金は数字だけ、文章の改行はそのまま入力できます。
4. まだ見せたくない場合は下書きで保存。サイトへ出す場合は「公開／更新」操作を行う。
5. サイトを再読み込みし、内容を確認する。

公開中の内容に対する下書き変更は、公開操作までサイトに反映しません。今回、下書きプレビューは未実装です。

## 動作確認チェック

| 操作 | 期待する結果 |
| --- | --- |
| 見出しを変更して公開 → 再読み込み | 新しい文章になる |
| 料金を33000にして公開 | `33,000` と表示される |
| FAQを追加・並べ替え・削除して公開 | サイトも同じ順番・件数になる。0件なら案内文になる |
| 写真を変更して公開 | 指定した場所の写真が変わる |
| 予約URLに自分のhttps予約先を設定して公開 | ヘッダー・本文・フッターのボタンが同じ予約先へ進む |
| 予約URLを空欄にして公開 | デモ案内になり、予約送信は行わない |
| 公開中の見出しを変え、下書きだけ保存 | 以前の公開内容のまま |
| SEOタイトル・説明を更新 | ブラウザのタイトルとHTMLのmeta情報が変わる |
| APIキーを誤ったものにして再起動 | `cms:check` がエラー。サイトでデモ料金へ勝手に戻らない |
| APIキーを元に戻して再起動 | 通常表示へ戻る |

Next.js側では永続キャッシュを使わず、再読み込み時に取得します。microCMS側の配信反映に少し時間がかかる場合は時間をおいて再確認してください。ビルドし直す必要はありません。
両方の接続変数が空欄のときだけ従来のデモを表示します。片方だけの設定、非公開コンテンツ、取得失敗、不正な必須データはエラーとして扱います。

## 自動テスト

```sh
npm test
```

ビルド後、既存記事CMSのテスト、CMSデータ検証、実際のNext.jsサーバーを使う結合テストを実行します。
結合テストはmicroCMS応答をローカルで模擬し、実際のmicroCMSコンテンツを変更しません。公開更新のHTML・SEO・予約リンクへの反映、空FAQ、HTML文字列のエスケープ、キー非露出、取得失敗、旧管理画面の本番遮断を確認します。
実サービスの下書き・公開操作、管理画面の分かりやすさ、スマホ操作は、上の手順で実アカウントを使って別途確認してください。

## 保守するときの入口

| ファイル | 責務 |
| --- | --- |
| `cms/microcms/client.js` | 公開オブジェクトAPIの取得。HTTPS、送信先、タイムアウト、エラーを制御 |
| `cms/microcms/normalize.js` | 必須項目・料金・予約URL・画像URLを検証し、画面が使う形へ変換 |
| `cms/microcms/gym.js` | サーバー専用の入口。環境変数とリクエスト内の取得共有 |
| `content/gym-premium/site.js` | CMS未接続のサンプル、任意文章の初期値 |
| `components/gym-premium/sections/` | セクションごとの表示。CMS固有の処理は置かない |
| `scripts/create-microcms-schema.mjs` | 日本語の表示名・初期値とスキーマの生成。`npm run cms:schema` で再生成 |
| `scripts/check-microcms.mjs` | キーを表示せず接続と入力を確認 |

項目追加は「スキーマ → 検証・変換 → 表示 → テスト」の順に確認します。すでに入力済みの項目を消す場合は先にデータを退避してください。

## 本番公開前の注意

- 現在はテンプレートデモとしてnoindexを維持しています。実店舗の公開時に正式URL・canonical・サイトマップと共に切り替えます。
- フッターのデモ注記、既存の仮写真・初期文章を実情報へ差し替えてください。接続しただけで本番公開完了にはなりません。
- 旧教材の `/admin` と `/api/*` は本番実行では標準で無効です。`ENABLE_LOCAL_CMS=true` はローカルの教材テスト専用で、本番の環境変数に設定しないでください。開発モードは従来どおりローカルで使用できます。
- 外部CMS障害時はエラー表示となります。必要に応じて監視やキャッシュ方針を別途検討します。誤ったデモ情報を表示することで障害を隠しません。

公式資料：[APIスキーマのインポート](https://document.microcms.io/manual/export-and-import-api-schema)、[公開コンテンツの取得](https://document.microcms.io/content-api/get-list-contents)、[フィールド形式](https://document.microcms.io/content-api/get-api-field-responses)。
