# 販売用Webサイトテンプレート

商品ごとのソース・説明書・販売素材を管理するディレクトリです。
既存のポートフォリオ用ファイルとは分けて扱います。

事業構想と価格の前提は[テンプレート販売の前提](../docs/template-business-premises.md)を参照してください。

## 取り込み済みテンプレート

`templates/` 直下に既存の3テンプレートを、共通CMS・部品・画像・テストとまとめて取り込んでいます。各テンプレートは同じNext.jsアプリの別ルートとして動作します。

| テンプレート | ローカルURL | CMS |
| --- | --- | --- |
| STELLA | http://127.0.0.1:3218/gym | microCMS対応・未設定時デモ |
| NAGI | http://127.0.0.1:3218/gym-premium | microCMS対応・未設定時デモ |
| FORGE | http://127.0.0.1:3218/gym-forge | デザインデモ・CMS未接続 |

```sh
cd templates
npm ci
npm run dev -- --port 3218
```

Node.js 22以上が必要です。3000番を使用中の別プロジェクトを避け、3218番を使用します。
元プロジェクトのソース・編集ガイド・テストを維持し、実際の環境変数、保存済み記事、Git履歴、依存パッケージ、生成物は取り込み対象から除外しています。
取り込み元の事業資料にある価格仮説などは原資料であり、このプロジェクトの現在の販売条件は上記の「テンプレート販売の前提」を優先してください。

取り込み時のビルド・テスト結果と未確認事項は[動作確認記録](IMPORT_CHECK.md)を参照してください。

取り込んだアプリの詳細は[テンプレート編集・構成ガイド](TEMPLATE_GUIDE.md)を参照してください。

## 商品を追加するときの構成

以下は構成例です。商品を作り始めるときに必要なものを追加します。

```text
templates/
  gym-starter/
    README.md             # 対象者・機能・対応環境・セットアップ
    CHANGELOG.md          # バージョンごとの変更履歴
    LICENSE.md            # 利用許諾・案件利用数・再配布の扱い
    src/                  # テンプレート本体のプロジェクト
    docs/
      setup.md            # CMS設定・環境変数・公開手順
      editing.md          # 顧客向けの更新方法
      support.md          # 問い合わせ窓口・対応範囲・期間
    sales/
      description.md      # 商品説明・価格・含むもの・対象外
      screenshots/        # デモ画像
```

`src/` はNext.jsアプリのプロジェクトルートとして扱う例です。
アプリ内の `src/` ディレクトリとは別です。既存のスターター構成がある場合はそちらを優先します。

## 商品ごとに決めること

- 誰が、どんな案件に使うか。
- CMSの種類、編集できる項目、必要な契約・外部費用。
- 対応するNode.js・Next.js等のバージョン。
- テンプレート単体の価格と、導入・カスタマイズの別料金。
- 1サイト用か、複数の顧客案件で使えるか。
- サポートの対象・期間、更新版の提供条件。
- 写真・フォント・アイコン・外部コードを再配布できるか。

## ソースと納品物の扱い

- 顧客の写真・文章・ロゴ・データ・認証情報を汎用テンプレートに含めない。
- 環境変数は値を除いた `.env.example` で説明し、本物のキーを保存しない。
- `node_modules/`、`.next/`、秘密情報、顧客データを販売ZIPに含めない。
- 販売ZIPは商品名とバージョンを付け、配布前に別の空ディレクトリでセットアップを確認する。
- 新規作成、CMS接続、編集、公開、フォームの送信を確認してから販売する。

## 公開範囲

この場所に置くこと自体は、非公開を保証しません。
販売用ソースを追加する前に、このGitリポジトリの公開範囲とサイト配信対象を確認してください。

有料商品のソースを公開したくない場合は、商品ごとの非公開リポジトリで管理し、
このディレクトリには商品一覧や管理方針だけを置く運用に切り替えます。
フォルダを分けるだけでは、Gitやホスティングの公開範囲は変わりません。
