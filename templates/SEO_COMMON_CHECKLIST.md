## 1. 必須：公開時の技術的SEO

### クロール・インデックス
- [ ] 主要ページがログインなしでHTTP 200として表示される
- [ ] 重要な文章・リンクを検索エンジンが取得できるHTMLに含める（SSR/SSG等は有効な手段。必須方式ではない）
- [ ] 実際のナビゲーションと内部リンクにクロール可能な `<a href>` を使用する
- [ ] 重要ページがトップ・カテゴリ・関連ページ等から辿れる
- [ ] 本番ページに誤った `noindex` / `nofollow` がない
- [ ] `robots.txt` が必要なクロールを妨げていない（`robots.txt` は非インデックス指定の代替ではない）
- [ ] `sitemap.xml` を用意し、正規URLの公開・インデックス対象ページを列挙する
- [ ] サイトマップを自動生成し、更新日時は実際の更新に合わせる。`robots.txt` にサイトマップの場所を記載する
- [ ] 404ページは適切なHTTP 404を返す。存在しないページに200を返さない
- [ ] URL移転時は適切な301/308リダイレクトを設定する
- [ ] 移転先は対応するページにし、無関係なページへの一括転送・ループ・不要な転送連鎖を避ける
- [ ] HTTP→HTTPS、www有無、末尾スラッシュなどURL表記を統一する
- [ ] 重複の可能性があるページは正しい `rel=canonical` を指定する（canonicalはヒントであり強制ではない）
- [ ] 本番URLを一元管理し、インデックス対象の正規ページは原則自己参照canonicalとする。プレビューURLを混入させない
- [ ] ステージングやプレビューは本番検索に露出しないようアクセス制御または適切なインデックス制御を行う

### ページ情報・情報設計
- [ ] 各重要ページに固有で内容を端的に表す `<title>` を設定する
- [ ] 各重要ページに内容に沿った meta description を設定する（検索結果表示文はGoogleが変更することがある）
- [ ] ページの主題を表すH1を設け、H2/H3を自然な階層で使う
- [ ] 意味が伝わる、安定したURL・slugを使用する
- [ ] メニュー、パンくず、関連記事などで自然な内部リンクを整備する
- [ ] 画像リンク・ボタンにも意味の分かるテキストを設定する
- [ ] ページの表示言語を `<html lang>` に設定する
- [ ] 多言語サイトのみ言語別URL・`hreflang` を正しく設定する

### モバイル・速度・アクセシビリティ
- [ ] スマートフォンで文字が読め、操作・フォーム入力がしやすい
- [ ] スマートフォンでも主要本文・リンク・構造化データが欠落せず、意味に合ったHTMLを使用する
- [ ] 適切なサイズ・形式で画像を配信し、寸法を指定してレイアウトずれを抑える
- [ ] ファーストビューの重要画像を不必要に遅延読み込みしない
- [ ] 不要なJavaScript、外部スクリプト、重いフォントを削減する
- [ ] Core Web Vitals を確認する：LCP ≤ 2.5秒 / INP ≤ 200ms / CLS ≤ 0.1（75パーセンタイルを目安）
- [ ] 実ユーザーデータとラボ計測を区別する。実測不足は記録し、Lighthouseの点数だけで合格や順位向上を断定しない
- [ ] 重要な画像には適切な代替テキストを付け、装飾画像は空altを使う
- [ ] HTTPSで公開し、混在コンテンツや重大な表示エラーがない

## 2. 必須：コンテンツ品質

- [ ] ページごとに「誰の・どんな疑問を解決するか」を定義する
- [ ] 見出しや本文は実際の検索意図に答え、誇張・キーワードの詰め込みを避ける
- [ ] 料金、サービス内容、会社・運営者、問い合わせ先など必要な事実を明確にする
- [ ] 一次情報、実例、独自写真、実績など固有の価値を示す
- [ ] 古い情報やリンク切れを定期的に見直す
- [ ] 大量の類似・薄い地域別ページを自動生成しない
- [ ] 事実確認と編集責任を持つ。AI生成文も公開前に確認する
- [ ] 文字数・キーワード密度を目的に情報を水増しせず、E-E-A-Tを単一の数値スコアとして扱わない

## 3. 必要に応じて実装

- [ ] ページ内容に合った構造化データ（JSON-LD）を追加する。タイプや必須プロパティはGoogleの現行仕様を確認する
- [ ] 構造化データの内容とページ上の表示情報を一致させる
- [ ] 必要なタイプだけを選び、架空の評価・資格・店舗情報を含めない。Schemaの妥当性とGoogleのリッチリザルト対象性を区別する
- [ ] OGP / Twitter Cardのタイトル・画像等を設定する（主目的はSNS共有であり直接的な順位保証ではない）
- [ ] 多拠点・実店舗では店舗情報、アクセス、Googleビジネスプロフィールを整備する
- [ ] ECなら商品、価格、在庫などの表示と対応する構造化データを検討する
- [ ] ページ分割・絞り込み・検索結果URLのインデックス方針を決める

## 4. CMSに標準搭載したい編集項目

CMSを採用する場合の基準。SEOのためだけにCMSやブログを追加する必要はない。今回の商品の採用範囲は事業方針と開発計画で決める。

| 対象 | 項目 | 仕様 |
|---|---|---|
| サイト全体 | サイト名、基本説明、ロゴ、既定OGP画像 | 各ページの未入力時に安全な初期値として使用 |
| 固定ページ | SEO title、meta description | ページ単位で編集可能。未入力時は内容に応じた初期値 |
| 記事・ページ | slug | 重複防止、変更時はリダイレクト運用 |
| 記事・ページ | 見出し、本文、画像、alt | 表示されるコンテンツとSEO情報を一致させる |
| 記事 | カテゴリ、公開日時、更新日時 | 実際の更新状況と一致させる |
| 記事・ページ | 下書き、公開状態、プレビュー | 未公開コンテンツの誤公開を防ぐ |
| 詳細設定 | canonical、noindex | 原則自動化し、必要な場合のみ管理者が上書きできるようにする |
| SNS | OGP title、description、画像 | 必要に応じて個別指定可能 |

**方針：** `robots.txt`、サイトマップ生成、canonical標準値、構造化データの基礎部分、メタデータ出力はサイト実装側で管理する。CMSの入力欄をむやみに増やさない。

## 5. リリース前の最終確認

- [ ] 本番URLを実機（スマホ・PC）で表示確認する
- [ ] 主要ページのソース／レンダリング結果にタイトル・見出し・重要本文・リンクがある
- [ ] `robots.txt`、`sitemap.xml`、canonical、noindexを本番で再確認する
- [ ] ページの404／リダイレクト動作を確認する
- [ ] Lighthouse / PageSpeed Insightsで速度と基本的な問題を確認する
- [ ] Search Consoleへ登録し、サイトマップを送信する
- [ ] URL検査で重要ページの取得・表示状態を確認する（登録されるまで時間がかかる場合がある）
- [ ] 要件に応じてGA4等を設置し、問い合わせ・予約等の成果計測を確認する（分析導入はSEO順位要因そのものではない）
- [ ] 計測タグのプライバシー・同意要件を確認し、GSC・GA4・GBPの設定状況、権限、担当、未完了作業を引き渡す
- [ ] 構造化データを導入した場合はRich Results Test等で検証する

## 6. 公開後の運用

- 毎週〜毎月：Search Consoleのインデックス状況、検索クエリ、クリック数、重要ページのエラーを確認。
- 毎月：問い合わせ等の成果、コンテンツの有用性、内部リンク、リンク切れを確認。
- 更新時：URL変更ならリダイレクト、重要ページ追加ならサイトマップと内部リンク、削除なら404/410や移転先を適切に設定。
- 大きなリニューアル時：URL対応表、リダイレクト、正規URL、計測、主要ページの検索状況を移行前後で比較。

## 7. 共通実装の完了条件（Definition of Done）

1. 重要ページをGoogleがアクセス・理解できる状態にする。
2. 主要ページのメタデータ・HTML構造・内部リンクが適切である。
3. モバイル表示と速度に重大な問題がない。
4. CMS採用時は本文・画像・ページ別SEO情報を安全に更新できる。
5. 公開前チェックとSearch Consoleでの公開後確認が可能である。

## 店舗サイト・AI検索の追加確認

- [ ] 実店舗では、店舗名・住所・電話番号・営業時間・サービス・公式URLをGoogleビジネスプロフィールと照合する
- [ ] 実際のアクセス方法・設備・料金・予約導線を掲載し、必要に応じて地図やアクセスリンクを用意する
- [ ] GBP側の設定をサイト実装と区別し、権限がなければ引き渡し事項にする。口コミの偽装や購入は行わない
- [ ] マップ順位、AI検索での引用、リッチリザルトを保証する表現がない
- [ ] AI専用タグや `llms.txt` をGoogle検索の必須条件として追加せず、必要性と公式の根拠を確認する
